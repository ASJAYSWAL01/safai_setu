# Safai Setu — Smart Waste Management

A Flutter app that connects **citizens**, **pickup-truck workers**, and the **department Head** in one waste-management workflow.

## Role-based portals

The app opens on a **role-select** page — each role has its own login page and its own portal:

| Role | Login | Portal |
|------|-------|--------|
| **Citizen** | Email / mobile + password, or **Continue with Google** | Report waste, track complaints, see the worker's proof photo when work is done |
| **Worker** (pickup truck) | **Worker ID** + password (ID is issued by the Head) | Accept collection tasks, navigate with live Google Map, share GPS location with the Head, take a **proof photo** after collecting waste — photo goes to the citizen and the Head |
| **Head** | Separate login page (email / mobile + password) | Generate Worker IDs (the **only** way workers are created), assign collection tasks with GPS coordinates, track all workers live, **review proof photos** (approve / reject) |

### Theme & info pages
- **Dark / light theme**: every profile page (citizen, worker, head) has a **Dark Theme** toggle that switches the whole app instantly. The palette is theme-aware (`AppColors` returns dark values in dark mode).
- **About Safai Setu**: mission, how the citizen → worker → head workflow works, features, and contact info.
- **Help & Support**: role-wise FAQs, contact details, and a report-a-problem action.

Both pages are reachable from **every** profile (citizen, worker, head).

### Login validation
- Citizens **cannot** log in on the Head portal or the Worker portal — role checks reject them with a clear message.
- Workers **cannot** log in on the Head portal.
- Worker accounts have **no email/mobile login** — only the Worker ID generated by the Head.
- Head accounts can only log in through the Head portal.

## Google integration

### 1. Google Maps (live map)
By default the app shows an offline map fallback that still renders marker coordinates, so everything works without an API key. To enable the real Google Map:

1. Create an API key in the [Google Cloud Console](https://console.cloud.google.com/) (enable the **Maps SDK for Android**).
2. Put the key in `lib/utils/config.dart` → `AppConfig.googleMapsApiKey`.
3. The key is also referenced in `android/app/src/main/AndroidManifest.xml` (replace the placeholder or wire it via `--dart-define`).

### 2. Google Sign-In (login)
The current Google flow is a **simulated demo** (`AuthService.signInWithGoogle`) because real credentials aren't configured. To go live:
1. Add the `google_sign_in` package and Firebase Auth (or your backend).
2. Replace the internals of `AuthService.signInWithGoogle` / `loginCitizen` — keep the same method signatures so no UI changes are needed.
3. Add the `google-services.json` config if using Firebase.

## Proof-of-work flow

1. Head **creates a task** with GPS coordinates and assigns it to a worker (or assigns an existing unassigned task).
2. Worker sees the task with a map, moves it through **En Route → Collecting**.
3. Worker **takes a proof photo** (camera) with an optional work note, then completes the task.
4. The photo + note are visible to:
   - the **citizen** who filed the linked complaint (Complaint Details → "Work Completed — Proof Photo"), and
   - the **Head** (Proofs tab → Approve or Reject).
5. Rejected proofs send the task back to the worker to redo; approved proofs mark the task verified.

## Architecture

```
lib/
  models/          AppUser (roles), CollectionTask, Complaint
  services/        AuthService — in-memory auth with role validation
  data/            AppRepository (tasks, live locations, proofs), MockDataRepository (citizen complaints)
  screens/
    auth/          Role select, citizen login/signup, worker login, head login
    worker/        Worker shell + dashboard, tasks, task detail (proof photo), live map, profile
    head/          Head shell + dashboard, workers, worker detail, generate Worker ID,
                   tasks, assign task, proofs review, profile
    ...            Citizen pages (home, complaints, map, hotspots, tracking, profile)
  widgets/         LiveMapView (Google Map or fallback), cards, buttons, badges, timeline
```

Everything is in-memory/demo data so the app runs end-to-end without a backend. To go to production, replace `AuthService` and `AppRepository` with Firebase/your API while keeping the same interfaces.
